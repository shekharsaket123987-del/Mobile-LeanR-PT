# Audit Section 6: Admin Clients Module Parity (Web vs Mobile)

Scope: Web `src/app/admin/clients/{page,new/page,[id]/page}.tsx` + `src/components/admin/{AdminClientsListClient,AdminClientDetailClient,AddClientForm}.tsx` + `src/lib/actions/admin-clients.actions.ts` + `src/lib/services/scheduling.service.ts` vs mobile `src/app/(admin)/admin-clients.tsx`, `admin-clients/[id].tsx`, `admin-clients/new.tsx` + `src/lib/data/admin-clients.ts`. Full pass — list screen, detail-screen action inventory + field-by-field diff, and create-client form diff, all covered.

## Findings

- **CLI-001 List screen — filters/search/columns.** WORKING CORRECTLY / at parity. Web (`AdminClientsListClient.tsx:19-26,52-64`) status filter set: all/not_paid/demo/created/active/paused/expired; search by name/phone/clientCode (`:32-38`). Mobile (`admin-clients.tsx:25-47,75`) has the identical 6-status set + search placeholder "Search by name, ID, or phone" matching field-for-field.
- **CLI-002 Detail screen — manual-controls action inventory.** WORKING CORRECTLY / mobile is a superset. Web `AdminClientDetailClient.tsx` wires: Adjust Package/Sessions, Grant Pause-Days, Transfer to Another Coach, Pause Subscription (no admin Resume), Log Measurement, Log Escalation, Log Refund Request, open-escalations list + resolve, Client Journey Timeline, Client Chats. Mobile `admin-clients/[id].tsx:170-246` has all of these plus Timeline/Chats/Escalations tabs.
- **CLI-003 Admin "Resume Subscription" button — mobile-only, not on web.** `admin-clients/[id].tsx:222-225` calls `resumeClientSubscription`; web has no equivalent admin action (`admin-clients.actions.ts` only exposes `pauseClientSubscriptionAction`; `resumeSubscription` is wired solely to client self-serve in `client-portal.actions.ts`). **Status: IMPLEMENTED BUT DIFFERENT (extra capability, not removed).** See "Requires product decision" below.
- **CLI-004 (FIXED) Detail screen was missing demographics, goals, medical notes entirely.** Web's header card shows height/weight/BMI, Goals, Medical Notes (`AdminClientDetailClient.tsx:227-251`, sourced from `onboarding` + `client.goals`/`client.medical_notes` in `admin-clients.actions.ts:183-193`). Mobile's `getAdminClientDetail` (`admin-clients.ts`, pre-fix) fetched none of this — the Overview tab had no such fields anywhere. **Fixed**: `admin-clients.ts` now selects `goals, medical_notes` on the existing `client_profiles` query, adds a `client_onboarding` read (age/gender/height_cm/weight_kg) and a local `calculateBmi` matching web's `utils.ts:57-61` exactly. UI: `admin-clients/[id].tsx` header card now renders height/weight/BMI row + Goals + Medical Notes blocks, right after the status badge (mirrors web's placement).
- **CLI-005 (FIXED) Detail screen had no progress/measurement history at all.** Web shows a "Progress Over Time" `MeasurementChart` plus full measurement fields (`AdminClientDetailClient.tsx:365-372`, sourced from `progressLogs` in `admin-clients.actions.ts:204,217`). Mobile could *log* a new measurement (`Log Measurement` panel) but had no read path to view past ones — an admin logging blind. **Fixed**: `admin-clients.ts` now reads `progress_logs` (last 30, same columns `admin-sessions.ts:92-96` already reads elsewhere in this codebase) into a new `progressHistory` field. UI: Overview tab now renders a `LightMeasurementChart` (weight trend, reusing the same chart component already live on the client-facing Progress screen) plus a latest-measurement breakdown (weight/body fat/muscle/waist/logged date), shown only when history exists — same conditional as web.
- **CLI-006 (FIXED) Session History rows were missing type badge and remarks.** Web's Session History shows Assessment/Regular type badge + status badge + date + remarks (`AdminClientDetailClient.tsx:377-386`). Mobile's Sessions tab showed only date + status. **Fixed**: `admin-clients/[id].tsx` sessions tab now renders a type badge (`session_type`) alongside status, plus `rating_note` as remarks text when present — using fields the query already fetched (`select('*')` on `bookings`) but the UI never rendered.
- **CLI-007 Session History `amountPaid` — not ported.** Web's `AssessmentBadge` shows `amountPaid` for assessment sessions (`admin-clients.actions.ts:198-202`). Mobile's `Booking` type (`types.ts:10-35`) has no `amount_paid` field, and I could not confirm within this pass whether the underlying `bookings.amount_paid` column exists/is populated on this schema. **Not implemented — left for product/schema confirmation** rather than guessing a column that might not exist.
- **CLI-008 (FIXED) Add Client form had no availability-check gate before submit.** Web's `AddClientForm.tsx` requires clicking "Check Availability" (`checkSlotAvailabilityAction` → `checkAdminSlotAssignment` in `scheduling.service.ts:725-763`) before `Create Client` is enabled (`canSubmit` requires `scheduleConfirmed`, `AddClientForm.tsx:96-106`) — this is the *only* protection against double-booking a coach during migration (web's own `createRecurringSlotsForClient` comment, `scheduling.service.ts:1440-1441`, confirms the actual slot insert is never re-checked server-side). Mobile had **no such function anywhere in the codebase** (confirmed by grep of `admin-clients.ts` exports) — `admin-clients/new.tsx` let an admin submit any coach/day/time combination with zero collision checking, silently double-booking a coach with no warning. **Fixed**: ported `checkAdminSlotAssignment`'s exact algorithm (`isDayTimeFreeForCoach`/`patternFreeAt`/grid-scan-for-alternatives) into a new `checkSlotAvailability` export in `admin-clients.ts`, using plain RLS-permitted reads (`coach_availability`, `recurring_slots`, `coach_profiles` — same tables `admin-availability.ts` already reads this way, no service-role/edge-function needed) plus the existing `getBookingSettings()` from `booking-wizard.ts` for the dynamic alternative-times window. `admin-clients/new.tsx` now has a "Check Availability" button + result panel (available / alternative times with this coach / alternative coaches at this time), and `canSubmit` is gated by `scheduleConfirmed` exactly like web. Deliberately kept web's own quirk: the check defaults to a 60-min duration (unpassed `durationMinutes`) even though real sessions are 45min elsewhere — not "fixed", just replicated, since web is the parity reference.
- **CLI-009 (FIXED) Add Client plan dropdown excluded archived/legacy packages.** Web's `listPackageOptionsAction` deliberately returns *every* `package_tiers` row, not just `is_active` ones — its own comment (`admin-clients.actions.ts:321-324`) explains this: a migrated client may be mid-plan on a since-retired package that must still be selectable. Mobile's `new.tsx` called `getMarketingPlans()` (`plans.ts:8-15`), which filters `.eq('is_active', true)` — the exact filter web explicitly avoids for this screen. A client on a legacy plan could not be correctly migrated. **Fixed**: swapped to `listAllPackages()` from `admin-settings.ts:23-27`, an already-existing unfiltered `package_tiers` read (used elsewhere for Plan Management) — reused rather than duplicated.
- **CLI-010 Add Client hour picker — matches web's own hardcoded-vs-dynamic split.** Web's initial hour dropdown is a hardcoded 5am–9pm grid (`AddClientForm.tsx:18`, independent of the live `system_settings` booking window), while only the post-check "alternative times" suggestions use the real dynamic window. Mobile's rebuilt hour picker (chips, `new.tsx`) now replicates this exact split rather than "fixing" the web inconsistency. **Status: WORKING CORRECTLY (matches web, including its own quirk).**
